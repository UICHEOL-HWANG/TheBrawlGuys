# TheBrawlGuys 고도화 제안 — 브롤스타즈 벤치마킹

작성일: 2026-10-12. 기획 제안이며 확정 PRD나 구현 완료 보고가 아니다.
저장소 코드·문서·저장된 화면 캡처를 검토했다. 이번 작업에서 게임 실행, 사용자 테스트, 운영 지표 조회는 하지 않았다. 기존 PHASES 체크박스와 구현 상태가 일부 달라 기능 존재는 코드를 기준으로 확인했다. 캡처는 현재 실행 화면과 다를 수 있다.

## 방향

**숲속에서 캐릭터를 골라 짧게 겨루고, 상대를 날리는 기술을 익히며 친구와 다시 하는 게임.**

브롤스타즈에서 참고할 것은 빠른 대전, 캐릭터 선택의 의미, 목적이 다른 모드, 성취와 자기표현이다. 우리 게임의 누적 대미지·넉백·아이템 쟁탈을 중심에 둔다. 체력 기반 슈터로의 전환은 제안하지 않는다.

## 최우선: 로비·선택 화면

### 현재 화면의 문제

- 저장된 온라인 로비 캡처에서는 참가자가 작은 텍스트 슬롯으로만 보이고 이름·캐릭터가 잘린다. 파티가 모였다는 느낌이 약하다.
- 오른쪽에는 캐릭터·준비·경기 방식·경기장·봇·시작·나가기 버튼이 비슷한 형태로 쌓여 행동의 중요도가 흐려진다.
- 캐릭터 선택은 4개 카드가 같은 크기이고 초상 영역이 짧다. 선택 중인 캐릭터의 존재감과 플레이 방식 설명이 부족하다.
- 경기장 선택은 작은 평면 도식 중심이라 실제 공간과 위험 요소를 상상하기 어렵다.
- 최근 코드에는 Sticker 테두리·깊이 표현이 있다. 다만 검토한 캡처는 부드러운 그림자 스타일이므로 최신 실행 화면을 다시 캡처한 뒤 시각 기준을 통일해야 한다.

### 시각 콘셉트: 숲속 대회 준비 캠프

짙은 숲색·크림색 패널·따뜻한 노랑의 주요 버튼을 사용한다. 나무 표지판, 깃발, 캐릭터 발판, 잔잔한 캠프파이어로 세계관을 채운다. 기존 캐릭터와 경기장 자산을 재사용하고, 배경의 대비는 캐릭터보다 낮춘다. 브롤스타즈의 구체적 로고·캐릭터·UI 아트는 복제하지 않는다.

| 화면 | 주인공 영역 | 보조 정보 | 주요 행동 |
|---|---|---|---|
| 메인 로비 | 선택 캐릭터의 큰 전신과 대기 모션 | 닉네임, 현재 모드·맵, 역할 한 줄 | 빠른 시작 |
| 친구방 | 중앙 2~4개 발판과 참가 캐릭터 | 방 코드, 팀, 준비·연결 상태, 경기 정보 | 방장: 경기 시작 / 참가자: 준비 |
| 캐릭터 선택 | 선택 캐릭터 확대와 시그니처 포즈 | 역할·강점·약점·필살기, 작은 4인 선택 목록 | 이 캐릭터로 선택 |
| 경기장 선택 | 선택 맵의 큰 실제 미리보기 | 위험 지형, 기믹, 공략 한 줄, 맵 목록 | 이 경기장 선택 |

### 메인 로비 상세

- 상단: 작은 로고, 프로필, 설정. 미구현 재화·상점·시즌패스는 표시하지 않는다.
- 중앙: 선택 캐릭터가 캠프 발판에 서 있다. 선택 시 짧은 포즈, 대기 시 호흡·무기 정리 정도로 절제한다.
- 왼쪽: 캐릭터 변경과 연습장. 성취 기능이 만들어진 뒤에만 현재 목표를 표시한다.
- 오른쪽 하단: 모드와 맵 미리보기, 큰 빠른 시작 버튼. 최초 진입 기본값은 기본 봇전, 이후에는 마지막 유효 설정을 사용한다.
- 모드 변경은 서랍/팝업으로 처리해 설정 화면을 여러 번 왕복하지 않게 한다. 친구방 입장은 별도 표시한다.

### 친구방 상세

- 중앙에 4개 캐릭터 발판. 발판 아래에는 이름·캐릭터·상태를 서로 다른 줄에 표시한다.
- 방장 표시, 내 캐릭터 표시, 준비 체크, 연결 경고를 색뿐 아니라 아이콘·텍스트로 함께 구분한다.
- 빈 슬롯에는 초대 또는 봇 추가를 표시한다. 봇은 명확히 봇으로 표기한다.
- 2대2는 양 팀을 공간적으로 묶고 팀 이름을 표시한다. 팀 변경 권한은 기존 방장 정책과 맞춘다.
- 오른쪽에는 맵 미리보기 → 규칙·기믹 → 준비 현황 → 시작 순서로 배치한다.
- 시작 비활성 이유를 구체적으로 표시한다: “P2 준비를 기다리는 중”, “P3 연결 중”.
- 참가자는 준비/준비 취소, 방장은 시작을 주요 버튼으로 사용한다. 나가기는 왼쪽 상단 보조 행동으로 이동한다.
- 설정이 바뀌면 무엇이 바뀌었는지 알리고 준비 상태의 재확인 정책을 적용한다. 캐릭터 선택·팀 변경·연결 끊김 중 시작되는 상황을 방지한다.
- 경기 후 같은 방에서 다시 준비한다. 한 참가자의 다시 하기 입력만으로 모두의 경기를 재시작하지 않는다.

### 캐릭터 선택 상세

4개 초상을 하단/왼쪽의 작은 선택 목록으로 바꾸고, 현재 선택한 캐릭터에 중앙 면적을 배정한다. 옆에는 역할 한 줄, 장점 하나, 주의점 하나, 필살기 설명과 짧은 시연을 둔다. 실제 수치와 연결하지 않은 별점 능력치는 만들지 않는다.

| 캐릭터 | 제안 역할 | 선택 화면 문구 예시 | 전투 차별화 검토 방향 |
|---|---|---|---|
| 바바리안 | 근접 압박 | 가까이 붙어 강하게 밀어내요 | 묵직한 타격과 공간 압박 |
| 로그 | 기동·기습 | 빈틈을 파고들어 몰아쳐요 | 진입·이탈과 후방 기습 |
| 나이트 | 범위 장악 | 넓게 휘둘러 접근을 막아요 | 접근 차단과 팀원 보호 |
| 메이지 | 원거리 견제 | 거리를 벌려 불덩이를 날려요 | 사거리와 투사체 압박 |

역할은 목표 제안이다. 실제 이동·사거리·판정과 맞는지 검증한 뒤 문구를 확정한다. 특히 바바리안과 로그는 현재 같은 권투 스타일을 공유하므로 필살기 외 차이를 먼저 검토한다. 새 버튼을 추가하기보다 기존 액션의 차별화를 우선한다.

### 경기장 선택 상세

- 작은 평면 도식은 보조 미니맵으로 남기고 실제 경기장 카메라 캡처를 큰 미리보기로 사용한다.
- “통나무 다리 — 발판이 부서져요”, “얼음 연못 — 멈추려 해도 미끄러져요”처럼 행동에 영향을 주는 설명을 먼저 보여준다.
- 선택 시 배경 조명·주변 소품이 해당 경기장 테마로 바뀐다. 저사양에서는 정적 이미지로 전환한다.
- 기믹 아이콘에 텍스트 라벨을 붙인다. 추천 표시는 플레이테스트 근거가 생긴 뒤 적용한다.

### 작은 화면과 연출

- 모바일 가로에서는 전시 영역과 조작 영역을 두 열로 배치하고, 낮은 화면에서는 상세 설명을 접되 선택·준비·시작은 항상 보이게 한다.
- 폰에서 카드 전체를 축소해 글자를 읽기 어렵게 하지 않는다. 세부 선택은 별도 시트로 연다.
- 터치 영역은 프로젝트 기존 기준을 따르고, 키보드·패드 포커스와 확정 상태를 구분한다.
- 일반 전환 150~250ms, 선택 포즈 0.4~0.8초를 초기 시안 값으로 사용한다. 모션 줄이기에서는 이동·흔들림을 제거한다.
- 여러 캐릭터 미리보기의 렌더링 비용을 측정한다. 비선택 캐릭터는 정적 초상으로 두고 하나의 큰 실시간 미리보기를 우선한다.

## 전투와 반복 플레이 고도화

1. **첫 판 단축:** 기존 튜토리얼을 이동·타격·링아웃 경험 중심의 짧은 입문과 선택형 심화로 나눈다. 필살기 터치 동시입력의 어려움을 먼저 테스트한다.
2. **캐릭터 정체성:** 기본 4인의 행동 차이와 시각 신호를 강화한다. 캐릭터 수 확대는 이후로 둔다.
3. **결과 화면:** 링아웃·아이템 활용·필살기 성과 등 실제 기록 가능한 항목을 요약하고 다음 판 또는 연습을 제안한다. 승패 외의 잘한 행동도 보여준다.
4. **성취 기록:** 캐릭터별 도전과 칭호·승리 포즈·이름표를 연결한다. 초기에는 능력치 성장 없이 실력과 외형에 집중한다. 봇전과 사람 대전 기록을 구분한다.
5. **2대2 거점 점령전:** 중앙 공간에서 상대를 밀어내는 재미를 검증한다. 넉백을 승리 목표와 직접 연결한다.

거점전 초기 실험 규칙: 120초, 단일 거점에 한 팀만 있으면 점수 증가, 양 팀이 있으면 중단, 전멸 대기 없이 리스폰. 거점 밖에서 원거리 공격만 해서는 점수를 얻을 수 없다. 동점 연장은 상한을 두고 종료한다. 점령 반경·리스폰 위치·원거리 우세·스폰 압박·봇의 거점 인식을 함께 테스트한다. 수치는 확정값이 아니다.

## 실행 순서와 완료 기준

아래는 소규모 개발과 기존 자산 재사용을 가정한 작업 묶음이다. 인력·실기기·아트 제작 범위를 확인하지 않아 달력 일정은 확정하지 않는다.

| 순서 | 묶음 | 완료 기준 |
|---|---|---|
| 1 | 로비·선택 화면 시안, 메인/친구방 권한·상태 설계 | 모바일·데스크톱에서 주요 행동과 선택 정보가 명확하고 화면 간 일관성 확보 |
| 2 | 로비 구현, 큰 캐릭터 미리보기, 맵 실제 미리보기, 빠른 시작 | 기존 봇전·로컬·온라인 진입 보존, 모든 준비/연결/빈 슬롯 상태 확인 |
| 3 | 입문 단축·캐릭터 설명·전투 피드백 | 첫 판에서 공격과 링아웃을 이해하는지 신규 사용자 테스트 |
| 4 | 결과 화면·안전한 재대전·성취 1줄 | 결과 집계 중복 없음, 재접속 후 일관성, 같은 멤버 재대전 확인 |
| 5 | 거점전 1종 내부 테스트 | 기존 모드 대비 재플레이 의향과 팀 협력 경험을 비교 |
| 6 | 성취 보상·친구 기능 확대 | 앞선 반복 플레이 개선이 확인된 뒤 확장 |

매치메이킹·랭크·대형 클랜·배틀패스·다수 재화는 뒤로 둔다. 이용자가 적은 단계에서 공개 대기열을 여러 개로 나누지 않는다. 공개 경쟁 모드는 현재 호스트 중심 온라인 구조의 신뢰성과 결과 검증을 별도로 평가한 뒤 추진한다.

## 검증 지표

| 지표 | 정의 | 초기 판단 기준 |
|---|---|---|
| 시작 성공 | 플레이 의도를 가진 로비 방문 중 실제 match_started 비율 | 현재 기준선 수집 후 개선 비교 |
| 로비 체류 | 로비 진입부터 시작까지, 접속 대기와 순수 조작 시간 분리 | 개인 봇전은 중앙값 15초 이내를 가설로 검증 |
| 첫 판 완주 | 신규 사용자의 첫 시작 경기 중 정상 완료 비율 | 기존 PRD 목표 80% 유지 |
| 재대전 | 경기 완료 후 60초 내 다음 경기 시작 비율 | 기존 대비 상승 여부, 승패·모드별 분리 |
| 화면 이해 | 5초 관찰 뒤 선택 캐릭터·모드·시작 행동을 맞히는지 | 탐색 테스트 5명 중 4명 이상, 통계적 확증과 구분 |
| 온라인 완주 | 실제 다기기 경기 중 정상 완료 비율 | 기기·네트워크별 실패 이유를 먼저 파악 |

위 목표는 업계 평균이나 실측 성과가 아니다. 소규모 테스트로 방향을 확인한 뒤 실제 사용자 자료로 조정한다. 기존 이벤트를 우선 재사용하고 필요한 속성·새 이벤트만 tracking-plan과 카탈로그에 추가한다.

## 첫 구현 묶음

**친구방 4인 캐릭터 전시 + 경기 정보 패널 + 준비/시작 버튼 위계 + 캐릭터 상세 선택 + 실제 맵 미리보기.**

전투 규칙을 바꾸기 전에 로비가 게임의 캐릭터성과 함께할 기대감을 전달하도록 만든다. 확정 시 PRD → PHASES → design 순서로 요구사항을 반영하고 기존 DS 컴포넌트와 선택 모델을 재사용한다.
